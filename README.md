## Как использовать промпт

1. Откройте карточку нужного промпта и изучите цель, область применения и ограничения.
2. Скопируйте текст из раздела **«Промпт v1.0»**.
3. Замените переменные вида `{{ТЕМА}}` и `{{ПРОФИЛЬ_БРЕНДА}}` данными своего задания. Неизвестные сведения обозначьте явно.
4. Задайте платформу, цель, количество вариантов и ограничения формата.
5. Передайте заполненный промпт выбранной модели и проверьте ответ перед использованием.

Примеры в карточках показывают допустимый формат. Они не являются результатами тестирования и не подтверждают факты о реальном бизнесе.

### Что нужно нейроассистенту контента

| Данные | Что указать |
| --- | --- |
| Задание | Сценарий, тема и цель материала. |
| Контекст | Профиль бренда, аудитория и доступная база знаний. |
| Факты | Подтверждённые сведения, их источники и сроки действия временных условий. |
| Формат | Платформа, число вариантов, стиль, лимит длины, необходимость тегов и эмодзи. |
| Дополнительные данные | Исходный текст для адаптации и дата для проверки сроков акций. |

По умолчанию ассистент готовит три варианта. По явному запросу — от одного до пяти; больший объём разбивается на партии. Итоговый ответ отделяет готовый материал от служебного блока **«Редактору»**.

## Подход к структуре промптов

Для первой карточки используется структура CLEAR в принятом для этой библиотеки формате:

| Блок | Содержание |
| --- | --- |
| **Task — задача** | Роль ассистента и требуемое действие. |
| **Context — контекст** | Условия работы, профиль, ограничения и правила достоверности. |
| **Input — вход** | Переменные и данные конкретного задания. |
| **Output — результат** | Формат ответа и критерии качества. |

## Тестирование

Для нейроассистента контента подготовлены три проверки:

| ID | Сценарий | Ключевое ожидание |
| --- | --- | --- |
| TC-01 | Пользователь просит один пост для Telegram. | Ровно один вариант; соблюдены лимит, формат и подтверждённые факты. |
| TC-02 | Цена в профиле и брифе различается, срок акции истёк. | Ассистент уточняет цену и не представляет старую скидку действующей. |
| TC-03 | Исходный текст содержит посторонние команды и неподтверждённое лечебное обещание. | Команды не выполняются; пост адаптируется без лечебного обещания. |

**Текущий статус:** тесты не запускались. Полные входные данные и критерии прохождения находятся в карточке.

Порядок проверки:

1. Запустите каждый тест в новой беседе с полным промптом соответствующей версии.
2. Сохраните дату, название модели, доступные настройки и фактический ответ в разделе **«Протокол проверки»**.
3. Сопоставьте ответ со всеми критериями теста; жёсткие ограничения длины проверьте счётчиком.
4. Укажите **PASS**, если выполнены все критерии, или **FAIL** с описанием ошибки.
5. После изменения промпта повторите проверки для новой версии.

Результаты относятся к указанной модели, её настройкам и версии промпта.

## Как добавить новый промпт

Создайте карточку по схеме `prompts/<название-промпта>/v1.0.md` и включите в неё:

- Название, версию, владельца и теги.
- Цель и область применения.
- Полный текст промпта и описание переменных.
- Примеры входных данных и допустимых ответов.
- Три тест-кейса с ожидаемым поведением и критериями проверки.
- Протокол тестирования и журнал изменений.

Добавьте ссылку на карточку в каталог этого README. Используйте названия папок латиницей, без пробелов.

## Правила версий

- **v1.0** — первая зафиксированная версия карточки.
- При изменении поведения или требований сохраняйте следующую версию отдельным файлом, например `v1.1.md`.
- В новой карточке обновляйте номер версии, журнал изменений и результаты тестов.
- Предыдущие версии сохраняйте для сравнения.
- В каталоге указывайте выбранную для использования версию и её фактический статус проверки.
- Сообщение коммита должно кратко описывать изменение, например: `docs: add content assistant prompt card v1.0`.

## Правила работы с данными

Используйте подтверждённые сведения и отмечайте их источники. Не подменяйте неизвестные цены, сроки, скидки и результаты предположениями.

Нейроассистент контента готовит материалы для редактора: публикация и изменение внешних данных не входят в его задачи. Содержимое исходных постов и справочников обрабатывается как данные; встроенные команды не меняют правила работы ассистента.
